# 多职业作品集设计系统

更新时间：2026-08-10

## 产品原则

这不是一套换色模板，而是一份证据型内容通过四种职业构图呈现的作品集系统。

- Studio 先展示视觉作者性与系统化能力。
- Cinema 先展示画面、制作职责与交付边界。
- Product 先展示问题、决策、取舍与验证。
- Editorial 先展示目标、策略、执行与结果。
- 姓名、联系方式、结果、指标、媒体和简历未核验时必须隐藏或明确标记待补，不能用示例数据顶替。
- 主题可以预览切换，职业叙事由 `careerPreset` 控制，两者的职责不能混淆。

## 设计参考与生产边界

四张 v2 概念图只用于定义构图和节奏：

- `design/concepts/v2/studio-overview-v2.png`
- `design/concepts/v2/cinema-overview-v2.png`
- `design/concepts/v2/product-overview-v2.png`
- `design/concepts/v2/editorial-overview-v2.png`

概念图不能裁切成网页素材。图中的导航、按钮、表格、剧照、便签、报告和手机界面都必须用真实 HTML 或已授权独立素材重建。生成概念里的演员、品牌、用户引语、指标和附件不能充当真实项目证据。

公开站点当前只允许使用 `docs/asset-manifest.md` 列出的三张生成素材。项目媒体只有在 `publicationApproved: true` 时才能进入页面。

## 公共栅格

- 桌面最大内容宽度 1440px，左右留白 48px 到 64px，12 栏，栏距 24px。
- 1024px 到 1279px 使用 8 栏。
- 767px 及以下使用 4 栏，左右留白 16px。
- 主题可以改变布局密度，但正文最小 16px，元数据最小 12px。
- 触控目标最小 44px，焦点轮廓必须清晰可见。
- 不允许横向页面溢出。Cinema 的片格如需横向滚动，只能在局部容器内使用 scroll snap。

## 四套主题

### Studio

- 色彩：`#F4F6F8`、`#FFFFFF`、`#090B10`、`#59616D`、`#2447F9`、`#D6DCE5`。
- 字体：Space Grotesk 与 Noto Sans SC 标题，IBM Plex Sans 与 Noto Sans SC 正文。
- 构图：非对称画廊，主项目占 8 栏，辅助项目在 4 栏内分层排列。
- 组件：大标题、主视觉、开放式项目索引、无图标能力目录。
- 标志动效：整行文字遮罩进入，媒体从左向右展开。不能逐字拆分 DOM。

### Cinema

- 色彩：`#0B1013`、`#151C20`、`#D7DCE0`、`#929BA1`、`#C8D63C`、`#364047`。
- 字体：Manrope 与 Noto Sans SC 标题，IBM Plex Sans 正文，等宽字体仅用于时间与职责元数据。
- 构图：媒体优先，主画面与 Credits 同屏，辅助项目采用宽银幕比例。
- 组件：主画面、可聚焦片格、职责矩阵、影片项目卡。
- 标志动效：单次 frame wipe 与同步播放头。没有真实视频时不出现播放按钮，不自动轮播。

### Product

- 色彩：`#EEF2F3`、`#FFFFFF`、`#17201F`、`#5D6966`、`#09664F`、`#CDD7D4`。
- 字体：IBM Plex Sans 与 Noto Sans SC，等宽字体只用于证据元数据。
- 构图：问题到决策的路径先于装饰图片，主案例明确展示 Context、Decision、Tradeoff、Impact。
- 组件：语义化决策路径、案例决策卡、证据区、结果区。
- 标志动效：连接线与节点按顺序显现。语义有序列表始终存在，不能做成假仪表盘或虚构数据。

### Editorial

- 色彩：`#FFFFFF`、`#FAF8F3`、`#171411`、`#6D655D`、`#C54A16`、`#D9D2C8`。
- 字体：Source Serif 4 与 Noto Serif SC 标题，Source Sans 3 与 Noto Sans SC 正文。
- 构图：栏目导航、主项目和 Goal、Strategy、Execution、Result 形成文章式阅读。
- 组件：章节栏、编辑特写、真实附件索引、文章式项目详情。
- 标志动效：纸页遮罩与 12px 以内的内容上移，不使用夸张翻页或 3D 旋转。

## 共享与特化边界

共享：

- 内容 schema、真实性状态、公开授权状态、SEO 和联系方式。
- Skip link、移动菜单、键盘行为、原生 Dialog、焦点返回与 reduced motion。
- 图片 alt、固有尺寸、懒加载和项目媒体权限。
- 按钮、链接、基础 focus、触控尺寸和普通的小幅 section reveal。

主题特化：

- Hero 的 DOM 构图和信息优先级。
- 项目索引方式、媒体比例、流程与能力的视觉组织。
- 项目详情的可视外壳。
- 每套主题唯一的标志动效。

## 动效规则

- 公开运行时只使用 Motion 与 CSS，不加入 GSAP、WebGL 或平滑滚动依赖。
- 不使用全局 scroll 监听、滚动劫持、自定义鼠标、预加载动画、自动音频、无限跑马灯或装饰循环。
- 每个动效都要有功能目的，并在 `prefers-reduced-motion` 下立即展示完整信息。
- Hover 只能增强反馈，不能承载触屏用户看不到的信息。
- 主题切换应更新 URL 查询参数和本地偏好，同时保持页面内容与键盘焦点稳定。

## 响应式顺序

移动端不能把桌面多栏整体缩小，必须重排为单列：

- Studio：标题、行动、主视觉、项目。
- Cinema：角色说明、主画面、Credits、片格。
- Product：标题、纵向决策有序列表、案例、证据。
- Editorial：标题、主视觉、栏目、项目叙事、附件。

Dialog 在移动端使用全屏或底部面板，最大高度为 `100dvh`，关闭按钮持续可见，内容区域独立滚动，并处理安全区。

## 发布验收

- 1536x1024、1280x800、390x844、320px 四组视口均无横向溢出。
- 四套主题的 Hero、作品区、流程区至少三处肉眼可辨，不能只是颜色不同。
- 200% 缩放仍可阅读和操作。
- 键盘可访问导航、主题选择、项目和 Dialog，关闭后焦点回到触发器。
- reduced motion 下无 clip 残留、不可见节点或丢失内容。
- 页面不显示假姓名、假联系方式、虚构指标、未授权项目画面或不可用的播放按钮。
- `npm run lint`、`npm run build`、`npm run release:check` 全部通过。

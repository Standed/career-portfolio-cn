# 文科生找工作，不该先被作品集代码卡住

我这次想解决一个很具体的问题。

求职已经够难了，作品集工具却常常默认使用者会写前端。设计师、剪辑师、产品经理、运营和文科生手里有文章、方案、视频、研究或活动记录，打开热门模板以后，先碰到的往往是 React 组件、配置项和部署命令。近期正在投简历的人，没有多少时间从头学一遍网站开发。

所以我做了一套开源中文求职作品集。使用者可以直接在 GitHub 网页上改一个内容文件，选好职业叙事和视觉主题，再交给 Vercel 部署。整套模板没有填写示例姓名、假邮箱和虚构数据。没有核实的内容会留在待补状态，页面不会替你硬撑出一份漂亮履历。

现在成品有四套主题。它们各自重做了首屏、项目区、流程区和动效节奏，同一份项目内容放进去，会得到四种很不一样的阅读体验。

## 四个岗位方向，四种作品集气质

Studio 面向视觉、UI、品牌和创意岗位。页面用冷白、近黑和蓝色做主色，项目像一组非对称画廊展开。标题和图片使用遮罩进入，画面有力量，节奏仍然克制。招聘方先看到作品，再顺着 Brief、个人职责、设计系统和结果往下读。

Cinema 面向导演、剪辑、动效、AI 视频和内容制作。它从石墨色全幅画面开始，用片格和 frame wipe 组织节奏，Credits 和交付状态一直留在容易找到的位置。模板当前没有获准公开的 Reel，因此页面也没有放一个点不开的播放按钮。项目画面未获授权时，页面只展示可信文字和公开状态。

Product 面向产品经理、用户研究和项目运营。首屏之后是一条从问题、判断、取舍走到交付的决策路径。项目详情强调 Context、Decision、Tradeoff 和 Impact，方便招聘方看清候选人怎样拆问题、怎样使用证据、哪些方案最后没有做。动效跟着决策顺序出现，不会抢过信息本身。

Editorial 面向内容、品牌、市场、新媒体和文科背景的求职者。它更像一份认真编过的刊物，纸白、墨黑和焦橙构成页面，中文标题使用项目内置的 Noto Serif SC。文章、栏目、活动、内容日历和运营机制都能放进来，阅读顺序从目标走到策略、执行和结果。

四套主题可以和四种职业叙事独立搭配。UX 设计师可以用 Product 讲决策，再选 Studio 展示视觉。品牌运营可以用 Editorial 讲目标与执行，再借 Studio 放大作品画面。AI 视频制作者可以保留 Cinema 的 Credits 与 Delivery，也可以选择更明亮的 Studio 外观。

## 我先翻了一圈 GitHub，才确定这套模板该怎么做

动手以前，我把 GitHub 上常见的作品集项目逐个看了一遍。academicpages 和 simplefolio 很容易理解，DevPortfolio 与 Magic UI Portfolio 把内容集中到配置文件里，用户改起来更省事。另一边，带 3D 场景或复杂滚动动画的作品集更有记忆点，编辑成本也明显更高。有些项目使用限制商业用途的许可证，只能拿来研究，代码不能直接搬进这套 MIT 模板。

看完这些项目，我基本确认了难点在哪里。容易改的模板经常长得相似，职业表达也偏向开发者。视觉记忆强的模板常常依赖复杂动画、特定素材或前端经验。对不会写代码的求职者来说，两边都差一点。

我又看了 Miro 的设计作品集评审、产品经理作品集指南、Vimeo 的剪辑师作品集建议，以及营销岗位的案例说明。不同岗位关心的顺序确实不一样。设计岗位需要尽快看到视觉能力和个人贡献。影视岗位要先看到代表画面，同时写清 Credits。产品岗位更关心问题、取舍和决策。内容与运营岗位要交代目标、本人职责、执行过程和已经发生的结果。

这也是四套主题没有停在换颜色的原因。作品集的版式应该顺着招聘方最想确认的事情走。

## 同一份项目，不用为每套主题重写

模板内部给每个项目留了同一组事实字段。它们包括项目概况、本人职责、关键动作、交付物、证据、结果、数据口径和公开状态。职业预设只调整标签和阅读顺序，不会改写项目事实。

普通使用者只需要优先编辑 `src/content/profile.ts`。文件里有九处 `EDIT HERE` 提示，姓名、目标岗位、教育经历、项目、能力、简历和联系方式都放在一起。`careerPreset` 决定项目怎样讲，`theme` 决定颜色、字体、版式和动效，两项可以分开选择。

我还把 `null` 做成了一个安全开关。真实姓名没有确认，就不展示姓名。联系方式没有同时填写显示文字和链接，按钮就不会出现。结果没有稳定口径，数字继续留空。简历没有经过隐私检查，下载入口也会隐藏。

这会让页面少一些东西，没有关系。为了填满版面写出假数字，把团队成绩算到自己头上，或者把客户后台和私人联系方式一起传到公开网站，后果都比留空更糟。

## 浏览器检查抓到了几处真问题

页面看着好看，只能说明检查做完了一小部分。

第一版中文标题在窄屏上会把“AI 能力”“内容”和“影像”拆成单字，读起来很别扭。现在标题会按中文词语分段，旧浏览器没有相应能力时也有安全回退。

字体也出过一个很隐蔽的问题。几组带空格的字体名称没有加引号，浏览器会把整条字体栈判成无效。源代码里确实写了字体设置，浏览器仍在使用回退字体。修完以后，我在浏览器里确认 Editorial 的 Noto Serif SC Variable 已经加载，不再只看 CSS 文件里写了什么。

320 像素宽的手机检查又抓到一处横向溢出。影视主题的流程片格在极窄屏下没有完全收回单列。调整以后，四套主题在 1536 乘 1024、390 乘 844、320 乘 844，以及模拟 200% 缩放的 768 CSS 像素宽度下都没有横向滚动，最小操作高度保持在 44 像素。

还有一处比排版更重要。项目弹窗曾经会在素材尚未批准公开时露出较详细的职责和证据。现在它同时检查内容核验状态和发布授权。只有两项都通过，详细交付、证据、结果、数据和媒体才会出现。弹窗关闭后，键盘焦点也会回到原来的项目按钮。

四套主题都支持减弱动效。系统开启这个选项以后，遮罩、位移和顺序动画会直接落到静态状态，正文不会因为透明度或裁切残留而消失。页面没有滚动劫持、自动音频、自定义鼠标和循环跑马灯。高级动效不该拿可读性去换。

## 能放进本地，不等于能放上网

这次整理过的候选图片一共有十一张，最后进入公开站点的只有三张。它们是专门生成的抽象主视觉，没有文字、真实人物和个人数据。

其余八张都留在 `local-review`。其中有尚未确认公开授权的项目角色、分镜和预告片单帧，也有包含真人、赛事转播图层与队徽的世界杯素材。它们可以帮助本地判断设计方向，不能进入公开仓库和线上发布包。

研究阶段用过 yt-dlp 读取公开视频的元数据和字幕，没有把第三方视频打进模板。发布检查还会核对 `public/media` 和构建结果只包含三张白名单图片，并扫描私钥文件和疑似访问令牌。代码使用 MIT 许可证，项目内置的中文字体继续保留 OFL 许可证与第三方说明。

授权这件事很容易被一句“素材网上找的”带过去。真要把项目交给求职者长期使用，边界必须写进文件结构和发布流程里，不能只靠使用者临上线时想起来。

## 第一次使用，只需要完成这几件事

先 Fork 仓库，再打开 `src/content/profile.ts`。从三个最能说明目标岗位的项目开始写，每个项目回答四件事，遇到了什么问题，你具体负责什么，做了哪些关键动作，最后交付或采用到哪一步。

没有数据就写已经发生的状态。课程作业、社团活动、实习任务、志愿项目和个人项目都能用，项目性质要说清楚。图片、成片、聊天记录和后台截图只有在脱敏并确认授权以后再上传。

选好 `careerPreset` 和 `theme`，在 GitHub 提交修改，然后用 Vercel 部署。这里仍然要按文档点几次按钮，我没有把它包装成完全零门槛。整个过程不用先学 React，也不用在几十个组件里到处找自己的姓名。

项目已经附上四类岗位填写指南、桌面与手机预览、隐私检查表、GitHub Pages 工作流和发布检查脚本。想先看成品，可以打开在线版本。准备做自己的作品集，再从开源仓库开始。

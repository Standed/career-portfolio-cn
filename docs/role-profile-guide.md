# 按岗位填写求职作品集

这份指南写给第一次做作品集的人。你可以用课程作业、个人项目、社团活动、实习任务、志愿项目或已经公开的工作案例。项目大小不重要，招聘方更想尽快知道你遇到了什么问题，具体做了什么，留下了哪些能核对的成果。

先挑三项最能说明目标岗位的项目。每项都用同一套结构整理，后面换 `careerPreset` 时，项目本身不用重写。

| 核心字段 | 要回答的问题 | 建议长度 |
| --- | --- | --- |
| Context | 当时要解决什么问题，有哪些限制 | 两到四句 |
| Role | 你负责什么，其他人负责什么 | 一到三句 |
| Actions | 你做了哪些关键动作，为什么这样选 | 三到六条 |
| Outcome | 交付了什么，是否采用，有什么反馈 | 两到四句 |

如果结果没有测量，就写清已经发生的事实。可以写完成、提交、采用、上线、进入下一轮，也可以写尚未上线或没有取得数据。别把浏览量、转化率、节省时间和团队成绩猜出来。

## 设计、创意与 UI

### 招聘方最先看什么

招聘方通常先看作品是否贴近岗位、主视觉和界面是否成熟、你的个人贡献能否一眼找到。漂亮成图只能说明结果的一部分。项目里还要让人看见你的判断，例如为什么改信息层级，为什么放弃某个方案，怎样让组件、版式或品牌语言保持一致。

### 建议准备的三类项目

1. 品牌或视觉系统项目。可以是品牌识别、活动视觉、栏目包装、海报系统或社团视觉升级。
2. 界面与体验项目。可以是网站、App、服务流程、交互原型或现有产品改版。
3. 信息与内容设计项目。可以是数据图表、报告、展览信息、内容模板或跨平台发布规范。

三项不必都是商业项目。课程作业和个人练习可以使用，只要写明项目性质，并保留从问题到成品的过程。

### 同一个项目怎么填

| 字段 | 设计岗位写法 |
| --- | --- |
| Context | 写目标受众、使用场景、原有问题和时间限制。不要只写提升视觉效果 |
| Role | 写你负责的研究、概念、界面、视觉、原型或交付规范，也写清协作者边界 |
| Actions | 选三到五个关键决定，例如重组信息、统一组件、测试动线、比较方案、整理设计规范 |
| Outcome | 写最终交付物、采用范围、评审意见和后续版本。没有业务数据就停在可核验的交付状态 |

### 可以使用的证据

- 草图、情绪板、用户流程和低保真原型
- 两到三个被放弃的方向及简短原因
- 组件、栅格、颜色、字体和状态规范
- 改版前后的同一页面对照
- 可操作原型、评审记录和交付清单
- 已获授权的成品截图或公开链接

### 没有数据时怎么写

可以直接写成下面这样。

> 项目完成了【具体交付物】，并在【评审、课程展示、团队使用或公开发布中的真实状态】得到使用。截至【核对日期】，尚未取得可核验的业务数据，因此本页只展示设计过程、交付范围与已经收到的反馈。

### 隐私与授权提醒

客户名称、内部界面、用户信息和未发布方案需要先确认公开范围。后台截图要遮住账号、联系方式、订单和业务数据。字体、图片、图标和品牌素材也要确认使用权。无法公开的项目可以重画结构示意图，并明确标注为脱敏复原。

### 可直接复制的首屏句式

> 我把【某类复杂问题】整理成【界面、品牌或视觉系统】，负责【你的真实职责】，重点解决【一个具体难点】。

> 我用【研究、信息设计、交互或视觉能力】完成【项目类型】，从【起点】推进到【已经核验的交付状态】。

## 影视、剪辑、动效与内容制作

### 招聘方最先看什么

招聘方希望尽快看到最强成片或代表镜头，同时确认片中哪些部分由你完成。剪辑、导演、动效、制片和声音的职责差别很大。把 Credits 放在显眼位置，比只写参与制作更有用。作品集还要说明素材条件、版本变化和最终交付状态。

### 建议准备的三类项目

1. 叙事或品牌成片。可以是短片、预告片、品牌视频、纪录片段或剧情内容。
2. 剪辑重构项目。可以展示同一批素材怎样通过结构、节奏、声音和镜头选择变成完整表达。
3. 动效与制作流程项目。可以是片头包装、信息动效、AI 视频流程、批量内容制作或跨平台版本交付。

### 同一个项目怎么填

| 字段 | 影视内容岗位写法 |
| --- | --- |
| Context | 写内容目标、受众、片长、素材条件、平台要求和交付时间 |
| Role | 写清导演、策划、分镜、生成、摄影、剪辑、调色、声音、动效或制片中的实际职责 |
| Actions | 写结构取舍、镜头选择、节奏修改、声音处理、版本迭代和质量检查 |
| Outcome | 写成片规格、交付版本、采用状态、审核意见和人工复核状态。播放数据未经核验就不写 |

### 可以使用的证据

- 剧本、分镜、镜头表和素材清单
- 剪辑时间线、版本记录和修改说明
- 同一段落修改前后的画面或节奏对照
- 动效测试、声音设计说明和调色参考
- 导出规格、机器 QC、人工审片记录和交付清单
- 已获授权的成片片段、海报、剧照与 Credits

### 没有数据时怎么写

可以直接写成下面这样。

> 项目已完成【成片或版本名称】并交付【接收方或使用场景】。当前能够核验的是【导出、审核、采用或发布状态】，播放、完播和转化数据尚未取得，因此不在作品集中推算。

### 隐私与授权提醒

演员肖像、音乐、字体、素材片段、平台水印和客户脚本都可能受到授权限制。未发布成片不能因为文件在本地就直接上传。时间线截图要遮住私人路径、账号和未公开素材名。团队项目还要写清 Credits，别把导演、摄影、声音或其他成员的工作算到自己名下。

### 可直接复制的首屏句式

> 我把【题材或传播目标】做成【成片类型】，负责【你的真实职责】，从【策划、分镜或素材起点】推进到【已经核验的交付状态】。

> 我专注【剪辑、动效、导演、声音或制作流程】，用【一种真实方法】解决【节奏、叙事、连续性或交付中的具体问题】。

## 产品经理、用户研究与项目运营

### 招聘方最先看什么

招聘方会先找问题、决策和取舍。成品界面只能说明项目做完了什么，还需要写清你如何确认问题，比较过哪些方案，为什么没有选择另一条路。产品和项目岗位经常依赖多人协作，Role 要写出你推动的环节，也要保留团队成员的贡献。

### 建议准备的三类项目

1. 从问题到方案的产品案例。可以是新功能、服务流程、内部工具或现有体验改进。
2. 用户研究与决策案例。可以是访谈、问卷、可用性测试、需求梳理或竞品研究推动的一次选择。
3. 跨团队交付案例。可以是项目排期、流程优化、上线协调、风险处理或运营机制建设。

### 同一个项目怎么填

| 字段 | 产品与项目岗位写法 |
| --- | --- |
| Context | 写用户问题、业务目标、已有证据、资源限制和不能回避的约束 |
| Role | 写你负责的调研、判断、方案、协调、推进或复盘，也写清谁拥有最终决定权 |
| Actions | 写怎样收集证据、拆问题、比较方案、处理分歧、控制范围和验证下一步 |
| Outcome | 写方案是否采用、功能是否上线、流程是否运行、团队是否继续使用。没有指标就写当前状态和已知反馈 |

### 可以使用的证据

- 访谈提纲、脱敏笔记、问题地图和研究结论
- 用户流程、需求清单、优先级依据和范围说明
- 方案比较、决策记录、风险清单和取舍说明
- 原型、PRD、排期、验收记录和上线说明
- 可用性测试、会议结论、反馈记录和复盘
- 已公开的产品页面或经过脱敏的交付截图

### 没有数据时怎么写

可以直接写成下面这样。

> 方案在【评审、测试、上线或内部运行中的真实阶段】完成了【可核验动作】。截至【核对日期】，团队尚未形成稳定的指标观察窗口，因此本页只说明决策依据、交付状态和已确认的用户反馈。

### 隐私与授权提醒

访谈原文、用户姓名、联系方式、内部路线图、经营数据和未发布功能都要脱敏。截图里的工号、群名、链接和客户信息也要处理。研究结论可以重新排版，原始记录不要整份上传。团队决策要写清你的推动和判断，避免把最终拍板说成个人独立完成。

### 可直接复制的首屏句式

> 我围绕【用户或业务问题】推进【产品、研究或项目类型】，负责【你的真实职责】，用【证据类型】完成【已经核验的决策或交付】。

> 我擅长把【模糊需求或协作问题】拆成【可验证的决策路径】，并推动【方案、流程或功能】走到【真实状态】。

## 内容、品牌、市场与新媒体运营

### 招聘方最先看什么

招聘方会先看目标受众、内容或活动目标、你的具体职责和最终产物。文章、视频、海报和活动页面都可以成为作品，关键是说明它为什么这样做，怎样发布，后来得到什么反馈。运营岗位还要让人看见持续执行和复盘能力，单篇内容很难说明完整工作方式。

### 建议准备的三类项目

1. 内容或栏目项目。可以是选题系列、公众号、短视频栏目、播客、专题文章或知识内容。
2. 品牌与 campaign 项目。可以是新品传播、活动策划、社群项目、品牌内容或多渠道发布。
3. 运营机制项目。可以是内容日历、素材库、用户反馈机制、社群流程或数据复盘机制。

### 同一个项目怎么填

| 字段 | 内容与运营岗位写法 |
| --- | --- |
| Context | 写受众、渠道、内容目标、发布条件、已有问题和资源限制 |
| Role | 写你负责的研究、选题、策划、写作、编辑、发布、协作、投放或复盘 |
| Actions | 写怎样判断选题、组织内容、协调素材、调整渠道、处理反馈和整理可复用方法 |
| Outcome | 写发布数量、采用状态、读者反馈、咨询或流程变化。数据要带平台、时间和统计口径 |

### 可以使用的证据

- Brief、选题池、内容日历和受众问题清单
- 大纲、脚本、初稿、修改记录和发布版本
- 渠道计划、素材清单、协作记录和发布截图
- 读者留言、用户反馈、咨询记录和复盘文档
- 有口径的后台数据截图和观察时间
- 可公开的文章、视频、活动页、模板或方法文档

### 没有数据时怎么写

可以直接写成下面这样。

> 项目完成了【内容、活动或运营交付物】，并在【真实渠道或团队场景】投入使用。截至【核对日期】，尚未取得可区分自然流量、付费推广或长期效果的数据，因此只展示发布事实、读者反馈和复盘结论。

### 隐私与授权提醒

后台账号、聊天记录、读者头像、群二维码、投放金额和客户资料不能直接公开。引用留言要遮住身份信息，并确认上下文没有被剪坏。商业合作、团队供稿和付费推广需要写明。文章、图片、音乐和第三方素材也要检查版权。

### 可直接复制的首屏句式

> 我把【内容、品牌或增长目标】拆成【策略与执行动作】，负责【你的真实职责】，留下了【可公开的成果类型】。

> 我围绕【受众或渠道问题】完成【栏目、campaign 或运营机制】，从【起点】推进到【已经核验的发布或采用状态】。

## 互联网通用岗位怎么映射

岗位名称经常换，项目证据却能跨岗位复用。先用 `careerPreset` 选择招聘方更熟悉的叙事顺序，再用 `theme` 选择与你的材料气质相符的视觉方向。

| 目标方向 | 建议 careerPreset | 可搭配 theme | 项目重点 |
| --- | --- | --- | --- |
| 品牌、视觉与 UI 设计 | `studio` | `studio` 或 `product` | 视觉判断、系统一致性、交付规范 |
| 交互与 UX | `product` | `studio` 或 `product` | 用户问题、流程、取舍、原型验证 |
| 影视剪辑与后期 | `cinema` | `cinema` | 结构、节奏、Credits、交付版本 |
| 动效与 AI 视频制作 | `cinema` | `cinema` 或 `studio` | 镜头、动效、制作流程、QC |
| 产品经理 | `product` | `product` | 问题、决策、范围、影响 |
| 用户研究 | `product` | `product` 或 `editorial` | 研究证据、洞察、决策变化 |
| 项目运营与流程管理 | `product` | `product` 或 `editorial` | 协作、风险、推进、运行状态 |
| 内容策划与编辑 | `editorial` | `editorial` | 目标、策略、执行、结果 |
| 品牌与市场 | `editorial` | `studio` 或 `editorial` | Brief、受众、campaign、采用结果 |
| 新媒体与社群运营 | `editorial` | `editorial` 或 `product` | 渠道、持续执行、反馈、复盘 |

`careerPreset` 负责项目标签和阅读顺序。`theme` 负责颜色、字体、版式和动效。两项可以独立混搭。UX 设计师可以用 `product` 讲决策，再选 `studio` 展示视觉。品牌运营可以用 `editorial` 讲目标和执行，再选 `studio` 增强作品画面。AI 视频制作者可以用 `cinema` 保留 Credits 与 Delivery，再按个人风格选择 `cinema` 或 `studio`。

最后回到同一个检查。每项项目都要让陌生人找到 Context、Role、Actions 和 Outcome。缺少哪一项，就补材料或诚实写明当前状态。能核对的事实比漂亮却含糊的结论更有说服力。
